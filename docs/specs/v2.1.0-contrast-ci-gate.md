# v2.1.0 — WCAG AA Contrast CI Gate

**Status:** specified, not yet implemented
**Scope:** both this repo's own PRs *and* the CI gate the generator emits into the design systems it produces.

This document is self-contained: it assumes only the current state of
`@benjaminmcosker/design-system-generator` and needs no other context to
implement.

---

## 1. Goal

Make a failing WCAG **AA** contrast check a hard, non-overridable blocker —
here in the generator's own repo, and in every design system the generator
emits. A failing check must fail the build and prevent the preview from
deploying, with no bypass.

WCAG AA thresholds (already the tool's own): **4.5:1** for normal text,
**3:1** for UI/non-text boundaries.

## 2. What already exists (do not rebuild)

The accessibility core is already here — this feature is mostly *wiring and
emission*, not new contrast logic.

- **Contrast math:** `src/tokens/contrast.ts` — `contrastRatio`, `bestTextOn`,
  `findContrastIssues`.
- **Enforcement at resolve time:** `src/tokens/parse.ts` → `resolveTokens()`
  throws `AccessibilityError` (which the CLI turns into `process.exitCode = 1`)
  when any of these pairs fail:
  - text on background (4.5), text on surface (4.5), muted text on background (4.5)
  - label on primary button (4.5), label on danger button (4.5)
  - danger text on background (4.5), success text on background (4.5)
  - primary as UI boundary (3), focus ring on background (3)
- **A dedicated gate command:** `dsg check <tokens>` (`src/cli.ts`) validates a
  spec and its AA contrast **without generating** — it already exits non-zero on
  failure. This is the gate primitive; the CI just needs to run it and be required.
- **Existing CI** (`.github/workflows/ci.yml`): `build-and-test` →
  `generated-a11y` (generates from `example/tokens.yaml`, runs axe-core on the
  generated components) → `chromatic` (publishes generated Storybook, currently
  `if: github.event_name == 'push'`, so **not on PRs**).

### Corrections to earlier assumptions
- Token source is a **YAML/JSON spec** (`example/tokens.yaml`, Zod schema in
  `src/tokens/schema.ts`) — **not Figma**.
- The palette is **single-theme** (one background/surface/text). There is **no
  dark theme**, so "light + dark" contrast checking is **out of scope** until a
  dark palette exists.
- Contrast pairs are **auto-derived** (`bestTextOn` picks the readable
  foreground), not a declared-pairs list.

## 3. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Where the gate lives | **Both** — this repo's PRs *and* emitted into generated systems |
| WCAG target | **AA** (4.5 text / 3 UI) — already the tool's thresholds |
| PR preview behavior (this repo) | **Enable Chromatic on PRs, gated** — Chromatic `needs:` the contrast job, so a failing PR never publishes a preview |
| What the gate checks (this repo) | **`example/tokens.yaml` + a fixtures matrix** including intentionally-inaccessible specs asserted to exit non-zero |
| Emitted gate's mechanism | Emitted workflow runs **`dsg check tokens.yaml`** (generator added as a devDep of the generated package) |
| No-override for generated systems | **Emit the workflow + a one-command `gh api` setup doc** (the scaffolder cannot set branch protection on a consumer's repo) |
| No-override for this repo | Branch protection with **"Include administrators"** (see §6) |

## 4. Workstream A — gate this repo's PRs

### 4.1 CI (`.github/workflows/ci.yml`)
1. Add a **`contrast`** job that runs on both `pull_request` and `push`:
   - `npm ci` → `npm run build`
   - `node dist/cli.js check example/tokens.yaml`
   - Run the **fixtures matrix** (see §4.2): every "pass" fixture must exit 0,
     every "fail" fixture must exit non-zero (assert the inversion so a gate
     that has stopped catching failures is itself a failure).
2. Make `generated-a11y` and `chromatic` **`needs:` `contrast`**.
3. **Enable Chromatic on PRs, gated:** drop the `if: github.event_name == 'push'`
   guard on the `chromatic` job (or broaden it to PRs) and set
   `needs: [contrast, generated-a11y]`. A red contrast check ⇒ Chromatic never
   runs ⇒ no preview. (`CHROMATIC_PROJECT_TOKEN` is already wired.)

### 4.2 Fixtures matrix
- Add `test/fixtures/contrast/pass/*.yaml` (accessible specs) and
  `test/fixtures/contrast/fail/*.yaml` (e.g. low-contrast text on background,
  a primary too close to its label).
- Two ways to assert, do both:
  - **Unit** (`test/contrast.test.ts` or a new file): `resolveTokens(parseTokens(...))`
    resolves for pass fixtures and throws `AccessibilityError` for fail fixtures.
  - **CLI/gate** (`npm run check:fixtures` script): loop the fixtures through
    `dsg check`, asserting exit codes. This is what the CI `contrast` job runs,
    so the gate is exercised exactly as consumers experience it.

### 4.3 Optional (reporting, nice-to-have)
- Add a `--json` flag to the `check` command (`src/cli.ts`) that prints
  `findContrastIssues(...)` output as JSON, so CI can emit a Step Summary table
  and `::error` annotations. Not required for the gate to function.

## 5. Workstream B — emit the gate into generated systems

The scaffolder currently emits **no** `.github/workflows` and does **not** copy
the source token spec into the output. Both are needed so a generated repo can
run `dsg check tokens.yaml` in its own CI.

Changes (all under `src/generator/`):
1. **`scaffold.ts`** — add:
   - `renderContrastWorkflow()` → YAML for the generated repo's
     `.github/workflows/contrast.yml`: on `pull_request` + `push`, `npm ci`,
     `npx dsg check tokens.yaml`. No `continue-on-error`, no skip path.
   - `renderTokenSpecYaml(spec)` (or copy the source file) so the spec ships in
     the output.
   - Update `renderPackageJson(tokens)` to add
     `@benjaminmcosker/design-system-generator` as a **devDependency** and a
     `"check": "dsg check tokens.yaml"` script.
2. **`generate.ts`** — add `write()` calls for `.github/workflows/contrast.yml`
   and `tokens.yaml`.
3. **`renderGeneratedReadme()`** — add an **"Enforce the gate (no override)"**
   section documenting a one-time `gh api` branch-protection snippet:
   ```bash
   gh api -X PUT repos/OWNER/REPO/branches/main/protection \
     -F required_status_checks.strict=true \
     -F 'required_status_checks.contexts[]=contrast' \
     -F enforce_admins=true \
     -F required_pull_request_reviews.required_approving_review_count=0 \
     -F restrictions=
   ```
   (`enforce_admins=true` is the no-override part.)
4. **Tests** (`test/generate.test.ts`) — assert the generated output contains
   `.github/workflows/contrast.yml`, a `tokens.yaml`, and the generator devDep.

## 6. No-override for THIS repo (branch protection)

Not code — a one-time repo setting to apply **after** §7:
- Require status checks: `contrast` (plus existing `build-and-test`,
  `generated-a11y`).
- Enable **"Do not allow bypassing the above settings" / "Include
  administrators"** so no one — admins included — can merge a red PR.
- Preview is already un-overridable via the `chromatic` `needs:` dependency,
  regardless of anyone's permissions.

## 7. Rollout order (load-bearing)

1. Land Workstream A (the `contrast` job runs and reports) **without** marking it
   required.
2. Confirm `dsg check example/tokens.yaml` is green on `main` (it is today — CI
   is green, and generation would throw otherwise).
3. **Only then** flip branch protection to required with "Include
   administrators" (§6). Do this out of order and merges are bricked with no
   admin unbrick, including the fix PR.

## 8. Out of scope for v2.1.0
- Dark-theme contrast (no dark palette exists yet).
- Figma / Tokens Studio sync.
- SARIF upload to the Security tab.
- Setting branch protection on consumers' repos automatically (documented `gh
  api` snippet only).
