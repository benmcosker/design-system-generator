# v2.8.0 — Listbox, Menu, and Combobox

**Status:** specified, not yet implemented
**Scope:** this repo only. Three additions to the generated component set (15 → 18
components), using the composite-widget conventions from Tabs (v2.2.0) and
Dialog/Tooltip/Toast (v2.5.0). No CLI, token, or theme-target changes.

This document is self-contained: it assumes only the current state of
`@benjaminmcosker/design-system-generator` (post v2.7.0) and needs no other context to
implement.

These were the "Menu, Combobox, Listbox" patterns explicitly deferred in the v2.2.0 and
v2.5.0 specs as "each its own release-sized effort." They are the three hardest WAI-ARIA
APG patterns left, and they share one core: **a collection of options with a single
active item**. This release builds that core once and layers the three on top.

---

## 1. Goal

| # | Component | Pattern | Key WCAG SCs |
| --- | --- | --- | --- |
| A | **Listbox** | Single-select listbox (APG "Listbox"), selection follows an explicit commit | 4.1.2 Name/Role/Value, 2.1.1 Keyboard |
| B | **Menu** | Menu button + menu of actions (APG "Menu Button") | 4.1.2, 2.1.1, 2.4.3 Focus Order |
| C | **Combobox** | Editable combobox with a listbox popup, list autocomplete (APG "Combobox with List Autocomplete", manual selection) | 4.1.2, 4.1.3 Status Messages, 2.1.1, 3.3.2 Labels |

None of the 15 existing components manage an *active descendant*, typeahead, or a popup
anchored to a trigger. `Select` deliberately wraps the native `<select>` and gets all of
this from the browser; these three exist for what native elements can't do (action menus,
filterable options, rich option content).

## 2. What already exists (do not rebuild)

- **Roving-focus / arrow-key code:** `Tabs` (`tabsTemplate()`, `ARROW_KEYS`, `tabRefs`)
  already implements Home/End/Arrow handling. The new components do **not** import it
  (generated components are standalone files), but follow the same shape and comments.
- **`React.useId()`** for stable id wiring — used by Tabs, TextField, Tooltip.
- **Focus rings:** one shared `:focus-visible` selector list in `renderStylesCss()`
  (`src/generator/css.ts`). New interactive classes join it.
- **Touch targets (v2.7.0):** every interactive control has a ≥24×24px hit area. Options,
  menu items, and the combobox input must meet this; reuse the `min-height` convention
  added in v2.7.0 Workstream A.
- **Reduced motion (v2.7.0):** any transition added here goes inside the existing
  `prefers-reduced-motion` handling. Prefer no transitions at all.
- **Status messages:** `TextField`'s `aria-live="polite"` error paragraph is the precedent
  for Combobox's result-count announcement.
- **`Button` / `IconButton`:** Menu's trigger is a consumer-supplied element (like
  Tooltip's), commonly `Button`. No new button code.
- **Per-component file pattern:** `ComponentFiles` / `allTemplates()` /
  `renderIndexTs()` — all three components fit the standard `{ Name, type NameProps }`
  export; **no `indexExports` override needed** (unlike Toast).
- **Doc generation** (`src/ai/docs.ts`) is generic over `ComponentFiles`; nothing to change.

### Corrections to earlier assumptions

**jsdom limits.** Verify before writing tests: `scrollIntoView` is not implemented in
jsdom (`Element.prototype.scrollIntoView` is undefined) — the shared active-option logic
must guard it (`el.scrollIntoView?.({ block: 'nearest' })`) or tests throw. Popover/anchor
positioning is CSS-only here, so there is nothing positional to test.

**`aria-activedescendant` is not exposed to axe as focus.** axe checks the *references*
(`aria-activedescendant` must point at an existing id; `aria-controls` and `aria-owns`
likewise) but cannot prove a screen reader announces the active option. Real screen-reader
behavior is manual-QA only; say so in the generated `.docs.md`, as Dialog does.

## 3. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Shared core | A small internal hook `useActiveOption` (index state, Arrow/Home/End movement, typeahead, wrap policy) **inlined into each generated file** — generated components stay standalone, no shared runtime file |
| Focus model | **Listbox & Combobox: DOM focus stays on the container/input; `aria-activedescendant` marks the active option.** **Menu: roving DOM focus** on `menuitem`s (APG Menu Button) |
| Listbox | Single-select only. Controlled (`value`/`onChange`) or uncontrolled (`defaultValue`). Selection **follows focus** is *off*: Arrow moves the active option; Enter/Space selects (avoids firing `onChange` while exploring) |
| Menu items | `menuitem` only. No `menuitemcheckbox`/`menuitemradio`, no submenus |
| Menu close | Escape (focus returns to trigger), Tab (closes, focus continues naturally), outside click, item activation |
| Combobox model | **List autocomplete, manual selection**: typing filters; active option is only chosen by Arrow keys; Enter selects the active option, else commits nothing. No inline autocomplete/auto-select |
| Combobox filtering | Case-insensitive `startsWith` then `includes`, pure function over `options`. Async/remote options are out of scope (consumer filters and passes `options`) |
| Combobox value | Selected `value` is separate from typed text; `onInputChange` is optional. Free-text values are **not** allowed (selection required) |
| Empty state | Combobox shows a non-option "No results" row (`role="status"`-announced, **not** `role="option"`) |
| Positioning | **CSS-only, below the trigger** (`position: absolute`). No flip/shift collision logic — same accepted tradeoff as Tooltip |
| Multi-select, groups, virtualization, creatable options | **Out of scope** (§9) |
| Dark theme | Still single-theme; no variants |

## 4. Shared option type

```ts
export interface ListOption {
  value: string;
  label: string;
  disabled?: boolean;
}
```

Each generated file declares its own copy (Listbox and Combobox use it; Menu uses
`MenuItem` below). Disabled options remain in the DOM with `aria-disabled="true"`, are
skipped by Arrow navigation and typeahead, and cannot be selected.

## 5. Workstream A — `Listbox`

**File:** `src/generator/templates.ts` — add `listboxTemplate()`; add to `allTemplates()`.
Implement first: it is the smallest and defines the shared logic.

**API:**
```ts
export interface ListboxProps {
  /** Accessible name for the listbox. Required: a listbox has no visible text of its own. */
  label: string;
  options: ListOption[];
  value?: string;
  defaultValue?: string;
  onChange?: (value: string) => void;
}
```

**Markup:** `<ul role="listbox" aria-label={label} tabIndex={0}
aria-activedescendant={activeId}>` containing `<li role="option" id aria-selected
aria-disabled>`. One tab stop; the container owns focus.

**Keyboard:** ArrowDown/ArrowUp (no wrap), Home/End, Enter/Space selects the active
option, printable characters do typeahead (single-char cycling; multi-char buffer cleared
after 500ms — the **one** timer in this release, tested with `vi.useFakeTimers()`).
Initial active option on focus: the selected option, else the first enabled one.

**CSS:** `.ds-listbox`, `.ds-listbox__option` (min-height per v2.7.0), `[aria-selected='true']`
(plus a check glyph via the existing status-icon approach, **not** color alone — SC 1.4.1),
`.ds-listbox__option--active` (visible indicator that is not color alone: outline).
Container joins the `:focus-visible` list.

**Tests:**
- Shipped axe test with a selected option and a disabled option.
- Shipped keyboard test: focus, ArrowDown ×2, Enter → `onChange` called with the third
  option's value; disabled option is skipped; Home/End; typeahead jumps to a matching label.
- `test/generate.test.ts`: generated `Listbox.tsx` contains `role="listbox"`,
  `aria-activedescendant`, and does **not** contain `<select`.

## 6. Workstream B — `Menu`

**File:** `menuTemplate()`; add to `allTemplates()`.

**API:**
```ts
export interface MenuItem {
  id: string;
  label: string;
  disabled?: boolean;
  onSelect: () => void;
}
export interface MenuProps {
  /** Accessible name for the menu (the trigger supplies the visible text). */
  label: string;
  items: MenuItem[];
  /** The trigger element. Must accept a ref and spread props (Button, IconButton, or a DOM element). */
  children: React.ReactElement;
}
```

**Behavior:** `Menu` clones the trigger to add `aria-haspopup="menu"`, `aria-expanded`,
`aria-controls`, `onClick`, and `onKeyDown` (ArrowDown/ArrowUp open and focus first/last
item; Enter/Space handled natively by the button). While open, items are
`<button role="menuitem" tabIndex={-1}>`; DOM focus moves to the active item (roving).
Arrow keys wrap; Home/End; typeahead as in Listbox; Escape closes and returns focus to the
trigger; Tab closes; activation calls `onSelect` then closes and returns focus to the
trigger. Outside `mousedown` closes (document listener added only while open, removed on
close/unmount).

**Markup:** wrapper `<span class="ds-menu">` (relative anchor, no semantics) around trigger
and `<ul role="menu" aria-label={label}>` rendered **only when open** (so a closed menu
adds nothing to the a11y tree), with `<li role="none">` wrapping each `role="menuitem"`.

**CSS:** `.ds-menu`, `.ds-menu__list` (surface, border, shadow, `z-index`),
`.ds-menu__item` (min-height, hover/focus background — focus indicator is an outline, not
color alone), `[aria-disabled='true']`. Items join the `:focus-visible` list.

**Tests:**
- Shipped axe test: render open (via ArrowDown on the trigger) and assert no violations in
  the open state; also closed.
- Shipped keyboard test: Enter on trigger opens and focuses first item; ArrowDown moves
  focus; Escape closes **and** `document.activeElement` is the trigger; selecting an item
  calls `onSelect` once and closes; disabled item is skipped and not selectable.
- Outside-click test with `user.click(document.body)`.
- `test/generate.test.ts`: generated `Menu.tsx` contains `role="menu"`, `role="menuitem"`,
  `aria-haspopup="menu"`, `aria-expanded`.

## 7. Workstream C — `Combobox`

**File:** `comboboxTemplate()`; add to `allTemplates()`. Implement last.

**API:**
```ts
export interface ComboboxProps {
  label: string;
  options: ListOption[];
  value?: string;
  defaultValue?: string;
  onChange?: (value: string) => void;
  description?: string;
  error?: string;
  required?: boolean;
  placeholder?: string;
}
```

Visible `<label>`, `description`, and `error` wiring mirror `TextField` exactly
(`aria-describedby`, `aria-invalid`, `aria-live="polite"` error) — do not re-invent;
copy its structure.

**Markup (APG 1.2):** `<input role="combobox" aria-expanded aria-controls={listId}
aria-autocomplete="list" aria-activedescendant autoComplete="off">` plus
`<ul role="listbox" id={listId}>` of `role="option"` rendered when open. Arrow keys move
the active option while DOM focus stays in the input.

**Keyboard:** ArrowDown opens (active = first enabled, or selected) / moves; ArrowUp moves;
Enter selects active option and closes (does **not** submit a surrounding form when the
popup is open: `preventDefault` only in that case); Escape closes, and a second Escape
clears the typed text (per APG); Home/End move the caret in the input (not the list) — a
deliberate APG-conformant choice; Tab closes without selecting. Typing filters and opens.
On blur with unchanged selection, input text reverts to the selected option's label.

**Announcements:** a visually-hidden `<div role="status">` updates with
`"{n} results available"` / `"No results"` after filtering (SC 4.1.3). Use the existing
visually-hidden class pattern from the v2.7.0 status icons.

**CSS:** `.ds-combobox` (reuses `.ds-input` base classes — do **not** fork input styling),
`.ds-combobox__list`, `.ds-combobox__option` (shares rules with `.ds-listbox__option` via
a grouped selector), `.ds-combobox__empty`.

**Tests:**
- Shipped axe test: closed, open-with-results, and open-empty states (three renders; relies
  on the existing `afterEach(cleanup)` in `axeTest()`).
- Shipped keyboard test: type "ap" → options filter; ArrowDown ×1, Enter → `onChange` with
  the right value and input text equals the label; Escape behavior (close, then clear).
- Shipped test: the status region text updates to the matching count.
- `test/generate.test.ts`: generated `Combobox.tsx` contains `role="combobox"`,
  `aria-autocomplete="list"`, `aria-activedescendant`, `role="status"`.

## 9. Out of scope for v2.8.0

- Multi-select Listbox/Combobox, option groups, virtualization, creatable/free-text values,
  async/remote option loading, inline autocomplete.
- Menu submenus, `menuitemcheckbox`/`menuitemradio`, context (right-click) menus.
- Collision-aware positioning (flip/shift) — below-trigger CSS only, as with Tooltip.
- Automated screen-reader verification of `aria-activedescendant` announcements —
  manual QA only (§2).
- Dark-theme variants.

## 11. Versioning note

Same as v2.5.0/v2.7.0 (`.releaserc.json`, semantic-release + conventional commits).
v2.7.0 is the latest release, so a `feat:` commit on `main` produces **2.8.0**.
**Land as one combined PR** (or a stack merged together): three separately-merged `feat:`
PRs would burn `2.8.0`/`2.9.0`/`2.10.0` for one logical release — the v2.2.0 mistake.
Do not hand-tag any version. The spec itself lands as a `docs:` commit, which does not
trigger a release.
