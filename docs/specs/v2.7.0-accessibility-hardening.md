# v2.7.0: accessibility hardening of the existing components

**Status:** specified, not yet implemented
**Scope:** this repo only. No new components and no new CLI surface. This release closes
five WCAG gaps that sit inside components already shipped (post v2.6.0, 15 components /
two targets). It ships as **one block**, not five per-component PRs: the fixes are
cross-cutting (four of the five are edits to the two shared files `src/generator/css.ts`
and `src/generator/templates.ts`), so slicing them into tiny units just multiplies
snapshot churn and review passes for no benefit. See §10.

This document is self-contained: it assumes only the current state of
`@benjaminmcosker/design-system-generator` and needs no other context to implement.

**Motivating reality:** the generator's whole pitch is "it refuses to emit an
inaccessible palette." That's true for *color contrast* and nothing else. A team can pass
`dsg check` and still ship 16px tap targets, motion that ignores `prefers-reduced-motion`,
text that won't scale, status conveyed by color alone, and inputs with no `autocomplete`.
Those are all WCAG failures the tool currently emits with a clean bill of health.

---

## 1. Goal

Close five gaps in the **generated output** so the components dsg emits meet the WCAG
Success Criteria they currently miss:

| # | Fix | WCAG SC | Level |
| --- | --- | --- | --- |
| A | **Touch targets** — every interactive control has a ≥24×24px hit area | 2.5.8 Target Size (Minimum) | AA |
| B | **Reduced motion** — all transitions honor `prefers-reduced-motion: reduce` | 2.3.3 Animation from Interactions | AAA (cheap, do it) |
| C | **Scalable fonts** — the font-size ladder is emitted in `rem`, not `px`, so it scales with the user's browser text-size setting | 1.4.4 Resize Text | AA |
| D | **Non-color status** — Alert and Toast convey tone with an icon + text, not color alone | 1.4.1 Use of Color | A |
| E | **Autocomplete hints** — text inputs carry (and are documented to carry) an `autocomplete` value identifying input purpose | 1.3.5 Identify Input Purpose | AA |

The bar is the one already set by the contrast gate: **AA**, with B taken along because it
is a two-line change.

## 2. What already exists (do not rebuild)

- **Token CSS** (`renderTokensCss()` in `src/generator/css.ts`): emits the font-size
  ladder at **lines 7–12** as `--ds-font-size-<label>: <px>px`, computed
  `Math.round(baseSizePx × scale^(i-1))` for `sm, base, lg, xl, 2xl, 3xl`. Spacing,
  radius and focus-ring width are also px. Workstream C changes **only the font ladder**.
- **Component CSS** (`renderStylesCss()` in `src/generator/css.ts`, 499 lines): one
  stylesheet, all `.ds-*` classes. Relevant current state:
  - **Interactive controls and their sizing today** — `.ds-button` (padding only, no
    min-size; `--sm` is `space-1 space-3`), `.ds-button--icon` (`padding: space-2;
    aspect-ratio: 1/1`), `.ds-input` / `.ds-select` (padding only),
    `.ds-checkbox__input` and `.ds-radio-group__input` (**`width/height: 1rem`** = 16px),
    `.ds-switch__input` (**`2.25rem × 1.25rem`** = 36×20px), `.ds-tabs__tab` (padding
    only), `.ds-accordion__summary` (padding only). Workstream A adds min-sizes here.
  - **Transitions today** — `.ds-button` `filter 120ms` (css.ts:63); `.ds-switch__input`
    `background 120ms` (256) and `::after transform 120ms` (267); `.ds-accordion__summary::before`
    `transform 120ms` (395); `.ds-tooltip` `opacity 120ms` (420). No `@keyframes` exist.
    Workstream B wraps all of these.
  - **Tone by color today** — `.ds-alert--{success,warning,danger}` set only
    `border-left-color` (css.ts:200–208); `.ds-toast--{…}` the same (485–493);
    `.ds-badge--{…}` set background/foreground (176–187). Workstream D addresses Alert and
    Toast (see §6.4 for why Badge is already compliant).
- **Component templates** (`src/generator/templates.ts`, 1745 lines): React + Storybook +
  an axe test per component. Relevant:
  - `Alert` (line 262): `role` is `alert` for danger else `status`; renders `title` +
    children, **no icon**. `tone: 'info' | 'success' | 'warning' | 'danger'`.
  - `Toast` (line 1486): `ToastItem` renders `role` alert/status, a message and an
    `IconButton` close; tone drives only the class. Same tone union as Alert.
  - `TextField` (line 116): `extends Omit<React.InputHTMLAttributes<HTMLInputElement>,
    'id' | 'aria-describedby'>` and spreads `{...rest}` onto the `<input>`, so
    **`autoComplete` already forwards today** — E is mostly typing, a story and a test,
    not new plumbing (see §6.5).
- **Test harness:** `axeTest(name, renderCalls)` helper (templates.ts) wraps each
  component's render in `expectNoAxeViolations`. CSS is covered by snapshot tests and the
  fixtures matrix; `renderTokensCss` / `renderStylesCss` / `renderShadcnThemeCss` all have
  snapshots that **will change** in this release (that is expected — §3).
- **CI** (`.github/workflows/ci.yml`): typecheck / test / build, the contrast gate, the
  fixtures matrix, generate-then-axe for React, and the shadcn theme-builds job.

## 3. Decisions (locked)

| Decision | Choice |
| --- | --- |
| Output changes on purpose | Unlike v2.6.0, **React output is NOT byte-identical** to the prior release. Fonts move px→rem, controls gain min-sizes, Alert/Toast gain markup. This is the point of the release; the regenerate-and-review diff is part of the work, not a regression. `dsg`'s **public API and token schema are unchanged** — every existing `tokens.yaml` still generates, just with accessible output. |
| Target-size floor | **24×24 CSS px** (SC 2.5.8, AA), not 44px (2.5.5, AAA). Matches the AA bar the contrast gate already sets, and avoids ballooning small/inline controls. Applied as `min-block-size` / `min-inline-size` (or intrinsic size, for checkbox/radio/switch). |
| Reduced-motion idiom | A single `@media (prefers-reduced-motion: reduce)` block scoped to `.ds-*` that sets `transition-duration: 0.01ms` and `animation-duration: 0.01ms` (near-zero, not `none`, so any `transitionend`/`animationend` handlers still fire). No JS. |
| Font unit | `rem`, computed as `px / 16` (the CSS initial root font size), rounded to 4 dp and trailing-zero-trimmed. **Only the font ladder.** Spacing, radius, focus width, icon box sizes and the checkbox/radio/switch dimensions stay as they are (rem or px) this release — see §8. |
| shadcn parity | The shadcn `@theme` `--text-*` bridge (from v2.6.0 §5.2) is emitted from the **same ladder**, so it becomes `rem` too. That is correct: Tailwind's own text scale is `rem`. No separate decision needed — it follows the ladder. |
| Non-color affordance | Alert and Toast get, per non-info tone, **(a)** a leading inline-SVG status icon (`aria-hidden="true"`, `currentColor`) and **(b)** a visually-hidden text prefix ("Success: " / "Warning: " / "Error: "). Icon serves sighted users who can't distinguish the color; the SR-only prefix serves screen-reader users, to whom color and `role` convey no severity. `info` gets neither (it is the neutral default). |
| Badge | **Out of scope for D, deliberately.** A badge's own text content ("Paid" vs "Overdue") differs per state, so tone is not the *only* visual means of conveying it — Badge already satisfies 1.4.1. Adding an icon would be nice-to-have, not a fix. Documented in §6.4 so it isn't mistaken for an oversight. |
| Autocomplete | Keep forwarding `autoComplete` via `...rest` (do **not** invent a bespoke enum — React's `InputHTMLAttributes['autoComplete']` already types the token list). The work is: assert forwarding, document it, and add it to `Select` if/where it applies. |
| New tokens / CLI | **None.** No schema change, no new flags. Purely a change to what the generator emits. |

## 4. Workstream A — touch targets (SC 2.5.8, AA)

In `renderStylesCss()`:

- `.ds-button` — add `min-block-size: 24px;` (md/lg already exceed it via padding; this
  guarantees `--sm` and any future variant). Keep `aspect-ratio: 1/1` on `--icon`; add
  `min-inline-size: 24px; min-block-size: 24px;` to `.ds-button--icon` so the icon box is
  never smaller than the floor regardless of icon size.
- `.ds-input`, `.ds-select` — add `min-block-size: 24px;` (padding already yields more,
  but this pins it against shrink and short fonts).
- `.ds-tabs__tab`, `.ds-accordion__summary` — add `min-block-size: 24px;`.
- `.ds-checkbox__input`, `.ds-radio-group__input` — grow from `1rem` to **`1.5rem`**
  (24px) `width/height`. Adjust `.ds-checkbox__input { margin-top }` so it stays aligned
  with the first line of the label at the new size.
- `.ds-switch__input` — grow to a **`2.75rem × 1.5rem`** track (from `2.25rem × 1.25rem`),
  bump the `::after` knob to `1.25rem` and the checked `translateX` to match, so the
  control is ≥24px tall and the thumb travel stays correct.

**Note:** the close button in Toast is an `IconButton size="sm"`; once `.ds-button--icon`
carries the 24px floor it is covered automatically — do not special-case it.

## 5. Workstream B — reduced motion (SC 2.3.3)

Append one block to `renderStylesCss()` (after all component classes so it wins on
cascade, though specificity already covers it):

```css
@media (prefers-reduced-motion: reduce) {
  .ds-button,
  .ds-switch__input,
  .ds-switch__input::after,
  .ds-accordion__summary::before,
  .ds-tooltip {
    transition-duration: 0.01ms;
  }
}
```

If a later component adds a keyframe animation, add its selector here with
`animation-duration: 0.01ms` too. There are no `@keyframes` today. No template changes.

## 6. Workstream C, D, E — emitter and templates

### 6.1 C: scalable fonts (`renderTokensCss`, css.ts:7–12)

Replace the px ladder with rem. Extract the conversion so both targets agree:

```ts
const remFromPx = (px: number) => `${parseFloat((px / 16).toFixed(4))}rem`;
// …
const px = Math.round(typography.baseSizePx * Math.pow(typography.scale, i - 1));
return `  --ds-font-size-${label}: ${remFromPx(px)};`;
```

- With the example tokens (`baseSizePx: 16`, `scale: 1.25`): `sm` → `0.75rem`, `base` →
  `1rem`, `lg` → `1.25rem`, `xl` → `1.5625rem`, `2xl` → `1.9375rem`, `3xl` → `2.4375rem`.
- The rounding is applied to the **px** first (unchanged from today) and then divided, so
  the pixel values at the default root size are identical to v2.6.0 — only the unit
  changes, and only the *scaling behavior* differs.
- The shadcn `--text-*` bridge (v2.6.0 §5.2) reuses this ladder and therefore also emits
  `rem`. Update its snapshot and the shadcn theme-builds assertions accordingly.

### 6.2 D: Alert non-color status (templates.ts, `alertTemplate`)

Add a per-tone status icon and a visually-hidden prefix. Suggested shape (inline SVG,
`currentColor`, `aria-hidden`; a `.ds-alert__icon` + `.ds-visually-hidden` class added to
`renderStylesCss()`):

```tsx
const TONE_META = {
  info:    { icon: null,     label: '' },
  success: { icon: checkIcon, label: 'Success: ' },
  warning: { icon: warnIcon,  label: 'Warning: ' },
  danger:  { icon: errorIcon, label: 'Error: ' },
} as const;
// in render: when meta.icon, render <span className="ds-alert__icon" aria-hidden="true">{icon}</span>
// and a <span className="ds-visually-hidden">{meta.label}</span> before the title/children.
```

- Add a `.ds-visually-hidden` utility to the stylesheet (the standard clip-rect pattern)
  and `.ds-alert__icon { flex-shrink: 0 }` (the alert is already `display:flex; gap`).
- `role` logic is unchanged. Icons are decorative (`aria-hidden`); the SR-only prefix is
  what carries severity to assistive tech.

### 6.3 D: Toast non-color status (templates.ts, `toastTemplate`)

Same `TONE_META` in `ToastItem`: a leading `.ds-toast__icon` (aria-hidden) and a
`.ds-visually-hidden` severity prefix before `.ds-toast__message`. Keep the existing
`IconButton` close control untouched. Factor `TONE_META` / the icon set so Alert and Toast
share it rather than duplicating the SVGs.

### 6.4 D: Badge is intentionally excluded

Do **not** change Badge. Its text content differs per tone, so color is not the only
visual means of conveying state (SC 1.4.1 is already met). Leave a one-line comment in
`badgeTemplate` pointing at this spec section so a future reader doesn't "fix" it and
break the byte-for-byte expectation for Badge.

### 6.5 E: autocomplete hints (templates.ts, `textFieldTemplate`)

`TextField` already forwards `autoComplete` through `...rest`. The deliverable is to make
that explicit and durable:

- Add a JSDoc line on `TextFieldProps` calling out `autoComplete` and linking SC 1.3.5, so
  it surfaces in Storybook autodocs. (No new prop — it's already in
  `InputHTMLAttributes`.)
- Add a `WithAutocomplete` story (`args: { label: 'Email address', type: 'email',
  autoComplete: 'email' }`).
- If a `Select`-based field collects an identifiable purpose, forward `autoComplete` there
  too (it extends the select attributes and spreads rest — confirm and document).
- Cross-reference in the README "accessibility" section: consumers must set
  `autoComplete` on fields collecting user info; the component forwards it faithfully.

## 7. Tests and CI

axe-core does not reliably catch target-size, reduced-motion, resize-text or use-of-color,
so most of these are asserted structurally, not via axe. Existing axe tests must still pass.

**CSS emitter tests** (`test/generate.test.ts` or a new `test/a11y-css.test.ts`):
- `renderTokensCss(example)` emits `--ds-font-size-base: 1rem;` and no `px` on any
  `--ds-font-size-*` line; assert the full ladder values in §6.1.
- `renderStylesCss()` contains `min-block-size: 24px` on `.ds-button`, `.ds-input`,
  `.ds-select`, `.ds-tabs__tab`, `.ds-accordion__summary`; `1.5rem` on
  `.ds-checkbox__input` / `.ds-radio-group__input`; the enlarged switch dimensions; and a
  `@media (prefers-reduced-motion: reduce)` block naming the five selectors in §5.
- Update every affected CSS snapshot deliberately (font ladder, sizing, motion block).

**Template tests:**
- Alert: each non-info tone renders a `.ds-alert__icon[aria-hidden="true"]` and a
  visually-hidden "Success:/Warning:/Error:" prefix; `info` renders neither; the four axe
  cases still pass.
- Toast: `ToastItem` per tone renders the icon + SR prefix; the close `IconButton` and
  live-region roles are unchanged; axe passes.
- Badge: a snapshot assertion that its markup is unchanged from v2.6.0 (guards §6.4).
- TextField: `render(<TextField label="Email" autoComplete="email" />)` — the `<input>`
  has `autocomplete="email"`. Select equivalent if applied.

**shadcn:** update the `renderShadcnThemeCss` snapshot for the rem `--text-*` values and
keep the theme-builds CI job green (the Tailwind utilities it asserts are unaffected by the
unit change).

**Fixtures / CI:** the fixtures matrix is about contrast and is unaffected. The
generate-then-axe React job still runs; add no new job — B/C/A produce no axe-detectable
change, and D's new nodes are covered by the per-component axe tests. Regenerate
`example/` output in the same PR so the committed sample reflects the new emitter.

## 8. Out of scope for v2.7.0

- **Spacing / radius / focus-width in rem.** Only the font ladder moves this release;
  scaling layout units is a larger, separately-reviewable change with its own visual
  blast radius.
- **44×44 (SC 2.5.5, AAA) targets.** We meet the AA floor; going to AAA would inflate
  small controls and is a design decision, not a bug fix.
- **`line-height` / text-spacing (SC 1.4.12).** The components set no `line-height` today;
  adding a scalable one is worth doing but is its own change.
- **Badge iconography** (§6.4).
- **A motion-reduction *setting* in tokens** (e.g. opt-out). The media query is the
  correct, user-controlled mechanism.
- Dark mode and `'use client'` directives (already tracked from v2.6.0 §8).

## 9. Definition of done

- Generated `styles.css` pins a ≥24px hit area on every interactive control, and
  checkbox/radio/switch render at ≥24px.
- Generated `styles.css` contains the `prefers-reduced-motion: reduce` block covering all
  five transitions.
- `--ds-font-size-*` (React) and `--text-*` (shadcn) are emitted in `rem`; pixel sizes at
  the default root size are unchanged from v2.6.0.
- Alert and Toast convey every non-info tone with an icon **and** a screen-reader severity
  prefix; Badge is unchanged; `dsg check` contrast behavior is unchanged.
- `TextField` forwards `autoComplete`, is documented to, and has a story + test proving it.
- Typecheck, unit, snapshot, fixtures and both CI jobs (React axe, shadcn theme-builds)
  are green; the committed `example/` output is regenerated; README has an accessibility
  section covering autocomplete and the target-size/motion guarantees.

## 10. Versioning and shipping note

Additive accessibility improvements to generated output, no breaking API or schema change:
a `feat:` commit, so semantic-release publishes **v2.7.0**.

**Ship as one PR (one block), not five.** Four of the five fixes edit the two shared files
`css.ts` and `templates.ts`; splitting them into per-fix or per-component PRs (as the
v2.2.0 work was split — see the five separate `feat/v2.2.0-*` branches in the log)
multiplies snapshot regeneration and review for changes that all land in the same two
files. Spec is self-contained; implement A–E together, regenerate `example/` once, review
the single output diff, and tag v2.7.0.
